ToyC 代码生成及优化作业要求
一、作业要求
实现一个 ToyC 语言的编译器，在前面任务的基础上能够实现汇编代码的生成，能够正确识别并输出源代码的RISC-V32汇编代码。

必须严格按照文法和终结符定义完成。

支持标准输入输出，忽略空白字符和注释。

 

二、ToyC 语言定义
2.1 文法定义
ToyC 语言文法如下，起始符号为 CompUnit：

编译单元 CompUnit → FuncDef+
语句 Stmt → Block | “;” | Expr “;” | ID “=” Expr “;”
           | “int” ID “=” Expr “;”
           | “if ” “(” Expr “)” Stmt (“else” Stmt)?
           | “while” “(” Expr “)” Stmt
           | “break” “;” | “continue” “;” | “return” Expr “;”
语句块 Block → “{” Stmt* “}”
函数定义 FuncDef → (“int” | “void”) ID “(” (Param (“,” Param)*)? “)” Block
形参 Param → “int” ID
表达式 Expr → LOrExpr
逻辑或表达式 LOrExpr → LAndExpr | LOrExpr “||” LAndExpr
逻辑与表达式 LAndExpr → RelExpr | LAndExpr “&&” RelExpr
关系表达式 RelExpr → AddExpr
                | RelExpr (“<” | “>” | “<=” | “>=” | “==” | “!=”) AddExpr
加减表达式 AddExpr → MulExpr
                | AddExpr (“+” | “-”) MulExpr
乘除模表达式 MulExpr → UnaryExpr
                | MulExpr (“*” | “/” | “%”) UnaryExpr
一元表达式 UnaryExpr → PrimaryExpr
                | (“+” | “-” | “!”) UnaryExpr
基本表达式 PrimaryExpr → ID | NUMBER | “(” Expr “)”
                | ID “(” (Expr (“,” Expr)*)? “)”
2.2 终结符特征
标识符（ID）：识别符合 C 规范的标识符。正则表达式：[_A-Za-z][_A-Za-z0-9]*

整数（NUMBER）：识别十进制整数常量。正则表达式：-?(0|[1-9][0-9]*)

空白字符和注释：忽略空白字符和注释。空白字符包括空格、制表符、换行符等；注释规范与 C 语言一致：

单行注释以 // 开始，到最近的换行符前结束

多行注释以 /* 开始，以最近的 */ 结束

2.3 语义约束
程序结构：必须包含一个名为 main、参数列表为空、返回类型为 int 的函数作为入口点。

函数：支持传入若干 int 类型参数，返回值可为 int 或 void。函数只能声明在全局作用域且名称唯一，不能声明在函数体内。函数不能作为值来储存、传递或运算。函数调用必须写在被调函数声明之后（支持递归）。返回类型为 int 的函数必须在每一条可能的执行路径上通过 return 语句返回一个 int 类型的值。返回类型为 void 的函数可以不包含 return 语句，如果包含，则不能有返回值。

语句：包括语句块（由大括号包围的语句序列）、空语句（只有分号）、表达式语句（表达式加分号）、变量赋值、变量声明、if-else 条件分支、while 循环、break、continue 和 return。语法和语义与 C 语言一致：没有返回值的函数调用表达式不能作为 if/while 条件或赋值语句的右值；break 和 continue 只能出现在循环中。

变量声明：支持声明 32 位有符号整数（int）类型的局部变量，每个变量声明语句只声明一个变量，且必须带有初始化表达式。变量的使用必须发生在声明之后。变量的作用域规则与 C 语言一致：变量的生命周期从声明点开始，到所在作用域结束时结束；函数形参在函数体内可见；语句块 Block 会创建新的作用域；内层作用域会屏蔽外层作用域的同名变量。

表达式：支持逻辑运算、关系运算、算术运算、括号表达式、变量引用、字面值和函数调用等 C 语言中的常见表达式。运算符的优先级、结合性和计算规则等与 C 语言一致：逻辑与、逻辑或运算符遵循“短路计算”规则；非零视为“真”、零视为“假”；除数不能为零。

2.4 特殊说明
使用的正则表达式在原有的基础上有扩充。

三、输入形式
输入为 ToyC 源代码。

以标准输入流输入。例如：

echo "int a = 1;" | ./your_compiler
在本地测试时可使用文件重定向。示例：

./your_compiler < test.c


此外，程序应支持一个可选命令行参数 -opt：
当未提供 -opt 时，评测器以功能正确为主，不要求实现优化；

当提供 -opt 时，编译器可以启用若干基础优化（例如常量折叠、简单的局部死代码消除或表达式简化），也可以选择忽略该参数。评测不会因是否实现优化而影响正确性判定，但你可以在实验报告中说明是否实现了优化和具体内容。

四、输出形式
所有测试用例确保无词法、语法、语义错误，直接输出源文件的汇编代码到标准输出流（stdout），例如：

<RISC-V32 assembly lines...>
本地测试时可使用文件重定向将输出保存到文件，例如：

./your_compiler < test.c > test.s

七、开发语言及环境
支持使用 C/C++、Java 或 OCaml 编程语言。

使用 Linux 环境，建议使用命令行工具进行编译和测试。

可用的构建系统：

C++：CMake（4.0.3）、Make

可用的第三方库：

C++：Flex、Bison/Yacc、ANTLR（4.13.1）
 
十、提示与建议
必须实现寄存器分配（register allocation）。目标架构为 RISC-V 32-bit，请勿生成任何 64-bit 指令或假定 64-bit 寄存器宽度。

寄存器分配算法可选用图着色（graph coloring）或线性扫描（linear scan）等常见方法。参考教材：


代码生成工作量较大，建议将编译器实现分为三段：前端（词法/语法/语义分析）、中端（中间表示、优化）、后端（目标代码生成与汇编输出、优化）。团队分工建议：两人实现中端、两人实现后端（或根据队员擅长调整）。在确保功能正确的前提下可以再进行优化实现。

在实现寄存器分配时，注意：通用寄存器数量有限（RV32 通常有 x1..x31，其中部分寄存器为约定用途），要正确处理调用约定（函数参数、返回值、被调保存、调用者保存寄存器）。同时考虑栈溢出/spill 处理和保存/恢复策略。

为便于调试与自动化验证，建议生成的汇编包含适当注释（可选）和必要的全局符号（如 .globl main / main: 标签），并避免使用汇编器/模拟器不支持的扩展指令。

Linux进程返回值是8位无符号整数，范围为0~255。超出该范围的返回值会被截断。
